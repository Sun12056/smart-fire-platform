## 3. 现有数据能否区分「走廊指示」与「楼梯指示」

### 3.1 代码事实

| 事实 | 值 |
|---|---|
| 疏散灯对象字段 | `id, type, x, y, area, direction, floorId, buildingId`（实测打印，无其他字段） |
| 5F 设备类型分布 | `evacuation_light` 11 / `emergency_light` 7 / `smoke_detector` 4 / `radar_sensor` 3 |
| `area` 取值分布 | `走廊` 17、`A区/B区/C区/D区` 各 1、`楼梯1/楼梯2/楼梯3/楼梯4` 各 1 |
| 节点类型枚举 | `NODE_TYPE = {ROOM, DOOR, CORRIDOR, STAIR, EXIT}`；图中实际有 room 24 / corridor 30 / stair 24 / exit 2 |
| 走廊建模 | `CORRIDOR` 是**渲染用矩形带** `{x:40,y:150,w:480,h:40}`；拓扑只在其**中心线 `y=170`** 上建走廊节点 |
| 楼梯接驳 | `STAIRS[i]` 提供 `corridorX/corridorY`，与走廊之间是**单条竖线段**（如 `(72,170)↔(72,45)`） |
| 设备↔拓扑关联 | **无** `nodeId` / `edgeId` / `segmentRef`，全靠坐标反推 |

### 3.2 结论：**不足以区分**

**冲突点【代码事实 + 几何推断】**：
- `EL-5F-01` 与 `EL-5F-13` 的 `area` 是 **`走廊`**，但几何上垂距 **0.00** 落在「走廊→楼梯」的**竖向引入段**上（EL-01 在 `CORRIDOR_W→STAIR_NW`，EL-13 在 `CORRIDOR_E→STAIR_NE`）。语义标签与几何归属直接冲突。
- 设备 `y=162` 落在 `CORRIDOR` 矩形带（y∈[150,190]）**内部**，却被判到竖向段上 —— 因为**拓扑里没有"走廊面"**，走廊只是一条 `y=170` 的线，而通往楼梯的竖线从 `y=170` 一路穿过矩形带。渲染几何与拓扑几何不一致。

### 3.3 缺失的安装 / 拓扑信息清单

| # | 缺失项 | 影响 |
|---|---|---|
| M1 | **设备安装属性字段**：无 `mountType`（壁装/吊装/地埋）、`orientation`/`facing`（灯具朝向）、`indicatorType`（方向指示灯 / 楼梯口指示 / 安全出口标志） | 无法判断灯具面对的是走廊轴向还是楼梯方向，也就无法决定该显示 left/right 还是"直下楼梯" |
| M2 | **设备↔节点/边的显式关联**：无 `nodeId` / `edgeId` | 只能靠坐标反推，拐角处必然出现归属歧义（本轮 EL-01/03/13 的根因） |
| M3 | **走廊的面建模**：拓扑只有中心线，`CORRIDOR` 带宽仅用于渲染 | 落在走廊带内但不在中心线上的灯具，会被判到竖向连接段 |
| M4 | **楼梯前室 / 防烟前室节点**：房间→走廊→楼梯之间只有一条竖线，没有"前室"这一可区分空间 | 无法表达"进入前室后方向改变"的语义，也失去了一个天然的归属边界 |
| M5 | **安全出口标志灯设备类型缺失**：`EXITS` 常量存在（出口A/出口B），但**没有任何设备**与其对应 | 出口/楼梯口标志与方向指示灯被混在同一个 `evacuation_light` 类型里 |
| M6 | **灯具可视/覆盖范围**（照射方向扇区、有效视距） | 即使判出方向，也无法验证该方向对该灯具是否"可见正确" |
