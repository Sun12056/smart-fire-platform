## 3. Root cause

`lightingDevices` 是一条**平行于权威链的本地台账**：它既不来自 `devices`，也不接收任何 WS/后端数据，
只由 `resetAll` 用旧台账深拷贝复活。因此：

```
Backend / WS ──► demoStore.devices ──► fireStore.devices ──✗─► LightingView
                                                              （断链）
mock/旧台账 ──► fireStore.lightingDevices ─────────────────────► LightingView
```

后果：demo 模式下 LightingView 永远看不到后端灯具（应急闪灯、方向、亮度、状态都拿不到），
只展示一套与演练无关的旧台账；B3-05 的「devices 唯一权威」在照明页并不成立。

**负面基线证据**（修复前跑本次专项，同一环境）：

```
T1 ✗ LightingView 灯具集合 = 权威 devices 的 emergency_light 子集
      → {"litOnly":96,"sampleLit":["FN-0001","FN-0006","FN-0011"],
         "sampleFs":["B001-EM-1F-02","B001-EM-1F-04","B001-EM-1F-06"]}
T1 ✗ 权威侧灯具全部能被 LightingView 看到 → {"fsOnly":148,"fsElTotal":148,"litTotal":96}
T3 ✗ 后端灯具运行态传播 → 37 台后端托管灯具全部 missing-in-lightingDevices
```

## 4. Fix（最小修改，2 个源文件 ≈ 12 行有效代码）

```
修复后
  Backend / WS ──► demoStore.devices ──► fireStore.devices
                                              │（只读派生投影）
                                              ▼
                                   fireStore.lightingDevices ──► LightingView
```

1. **`fireStore.js`**：`lightingDevices` 由 `ref(旧台账)` 改为
   `computed(() => devices.value.filter(d => d.type === 'emergency_light'))` —— 只读派生，禁止写回；
2. **`fireStore.js`**：删除 `resetAll` 里对 `lightingDevices` 的深拷贝赋值（devices 已重建，投影自动收敛）；
3. **`fireStore.js`**：`lightingStatus.currentDevice` 初始化 / 重置时指向统一集合的首台设备
   （旧台账对象已退休，避免聚合态仍握着退休对象）；
4. **`LightingView.vue`**：仅补注释，声明本页灯具唯一来源 = `store.lightingDevices`
   （fireStore.devices 的只读投影），不得反向写入设备业务状态 —— **未改任何逻辑**。

`devices` / demoStore / WS / 3D / 路线算法 / GLB / mock 数据结构：**零改动**。
