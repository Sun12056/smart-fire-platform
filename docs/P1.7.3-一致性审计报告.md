## 2. 逐项结论（对应阶段目标）

### P1.7.3-02 人员 —— **通过（静态）**
* 链路闭合：`engine.tickWorld` → `personDTOs` → `demoStore:104/125` → `fireStore:484-493` → 2D(`PersonView:527-552`) / 3D(`PersonLayer3D:68-71`)。**2D 与 3D 拿到的是同一个响应式数组中的同一批对象引用。**
* 「标配三态」都有后端写入点：正常→ `engine.ts:520-522`（`status:safe`）；疏散→ `engine.ts:255-257`（`evacuating/status/movementType`）；滞留→ `engine.ts:296-299`（`retained/status:'stranded'/movementType:'static'`）；救援→ `engine.ts:322`（`located`）→ `:343`（`rescued`）。
* **待运行时取证**：5 正常 / 5 疏散 / 2 滞留的逐人核对尚未做（需 Golden Path  Runner），本轮未做运行时证据（不改代码，也不跑 demo 服务）。

### P1.7.3-03 设备 —— **不通过**
* 后端迁移齐全（`engine.ts:136-138` 烟感、`146-157` 应急照明/方向），但：
  * 三个页面/按钮可在无守卫情况下本地抢写同一批字段（第 21 条）；
  * 灯光页走另一份数据源（第 22 条）+ UI 直写（第 23 条）；
  * 3D 只吃 `emergencyMode` 布尔，逐设备差异不可见，`emergencyFlash` 成为死字段（第 24 条）。

### P1.7.3-04 火灾 —— **通过（有整改项）**
* 唯一权威 + 3D canonical 取模正确；风险集中在 2D 用旧别名比较（第 27 条）与 `BuildingMap` 不渲染（第 29 条）。

### P1.7.3-05 方案/路线 —— **通过后是有条件的**
* 覆盖面：确认为**整栋楼**（`engine.ts:180-189` 全楼 persons 入参 + `DemoRoom.ts:362-421` 门禁），非只针对 5F-A 区。
