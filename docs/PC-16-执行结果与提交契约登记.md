## 1. 主结果分类（[裁定]，摘要可恢复）

| 优先级 | 触发条件 | 主结果 |
|---|---|---|
| 1 | 发生实际异常 | EXCEPTION |
| 2 | 无异常 + ≥1 项必需操作已确认未完成 | PARTIAL |
| 3 | 无异常 + 无已确认未完成 + ≥1 项无法确认 | UNCONFIRMED |
| 4 | 全部必需操作确认完成 + 全部提交条件满足 | SUCCESS |
| — | 业务门禁拒绝（独立于写入阶段） | REJECTED |

- REJECTED 属门禁阶段，先于写入阶段，不与另四类构成同阶段互斥。
- 优先级为判定次序，非价值排序，不得掩盖实际操作状态。
- 完备性口径（已定案）：五类在已定义契约条件下有预期边界，但
  **对全部实际执行情形的完备性未经证明**；当前源码尚不能证明该分类体系可执行。

## 2. Q-T（[裁定]，原文可恢复）

当同一轮内同时满足：① ≥1 项本轮必需操作已确认未完成；② ≥1 项本轮必需操作
无法可靠确认完成状态；③ 未发生实际异常 → 整轮主结果取 PARTIAL。

- 诊断明细必须同时保留四类：已确认完成 / 已确认失败或未完成 / 无法确认完成状态 /
  已发生的设备字段副作用。
- 不得将"无法确认"归类为"已确认失败"。
- 不得因主结果为 PARTIAL 而省略或覆盖 UNCONFIRMED 明细。
- 不得将该轮认定为成功提交或 N4。
- PARTIAL 语义 = "整轮已确认未全部完成"，不代表所有操作已查明，不蕴含未知操作必定失败。

## 3. Q-P（[裁定]，摘要可恢复）

- 实际异常 → 主结果一律 EXCEPTION。
- 仍须保留全部操作级诊断（含设备字段副作用）。
- 不得假设回滚。

## 4. 提交状态与 N4（[裁定]）

### 4.1 已恢复的提交约束面（摘要可恢复）

- 主结果为 PARTIAL / UNCONFIRMED / EXCEPTION 等非成功轮次时：
  - N4 = 否；
  - 最近成功提交记录不更新；
  - 全场级 pendingValidation 应保持 true（契约要求，非运行时已实现）。
- 仅当全部必需操作确认完成且全部提交条件满足时，才允许更新最近成功提交记录
  并将 pendingValidation 置为 false。
- 未成功轮次不得假设未完成/无法确认的操作已回滚。

### 4.2 完整触发条件（原文未恢复，摘要可恢复）

> 以下为**摘要记录**的 N4 触发条件，**非原始定义**。摘要不能替代原始定义，
> 写入成功也不能仅凭"赋值存在"或"未抛异常"来认定。

摘要记录的五项条件：

1. 所有前置门禁通过；
2. 正常到达提交点；

### 6.1 投影清理规则（摘要可恢复，原始裁定原文未恢复）

> 以下为 **Q-C、Q-E、Q-H、Q-K 的摘要级登记**，非原文引述。

- **Q-C**：按事件类别决定投影清理策略。
  - 出口证据、火源或阻塞变化：不主动清空投影，但旧关联立即失去有效性资格。
  - 路线几何、路线集合/方案集合或所有权变化，导致旧绑定无法证明有效：清理三类投影。
  - 切换建筑（包括命中缓存）：清理三类投影。
  - 全部路线为 BLOCKED：清理三类投影，不提交。
  - 其他拒绝按拒绝原因决定清理策略；异常不保证回滚，旧关联不能作为有效性证据。

- **Q-E**：路线几何、路线集合或方案所有权变化，导致旧绑定无法验证时，
  清理 `routeDeviceBindings`、`routeDirectionVerdicts`、`routeNoPathRouteIds`。

- **Q-H**：R3 `STATUS_GATE_FAILED` 不清理上述三类投影，但旧关联立即失去有效性资格；
  残留投影不证明有效。

- **Q-K**：R1 `NO_ACTIVE_PLAN`（`!bp`，方案所有权无法证明）清理上述三类投影；
  设备字段禁止写入。清理失败不构成提交，也不构成 N4；不要自动扩展到 R4。

1. 上述内容是**已有历史摘要**，不是原始裁定全文。
