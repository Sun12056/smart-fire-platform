## 7. 问题清单

### P0-01 · 疏散方案选择双写：前端显示方案 ≠ 后端执行方案
- **ID**：P0-01
- **Severity**：P0
- **File**：`src/stores/fireStore.js:2749`（`setActiveBuildingPlan`）；`src/views/DashboardView.vue:628`；`src/views/RoutePlanView.vue:107`；`src/stores/demoStore.js:224/233-245`（`selectPlan / confirmRoute`）
- **Line**：fireStore.js:2749-2766 / 1130；DashboardView.vue:628、1301-1304
- **Current behavior**：管理员点 PLAN-B/C 时，View 直接调 `store.setActiveBuildingPlan(id)` → 只改 **`fireStore.activeBuildingPlanId`**（未被 demoGuard 拦截）；而 `demoStore.selectedPlanId` 仍为 `null`、`demoStore.activeBuildingPlanId` 仍是后端 PLAN_ROUTES 时下发的推荐方案。确认执行时 `confirmEvacuationPlan()` → `dispatchDemoCommand('CONFIRM_ROUTE', d => d.confirmRoute(d.selectedPlanId || d.activeBuildingPlanId))` 取的是 **demoStore 侧**，于是后端执行的仍是旧（推荐）方案，随后快照又把前端的 activeBuildingPlanId 覆盖回该方案。
- **Why it is a problem**：① **操作员的选择被静默丢弃**；② 确认瞬间「前端显示的当前方案」与「后端实际执行方案」不一致，属于前端状态机与后端状态机不同——正是一条命令决定了整栋楼的疏散路线；③ 同时它是 B1 Demo Guard 的**唯一漏点**（demo 模式下的本地业务写入）。
- **Authority expected**：demo 模式下「管理员点选方案」应只有一个权威落点：`demoStore.selectedPlanId`；`fireStore.activeBuildingPlanId` 只能是「snapshot(activeBuildingPlanId)」的镜像；`setActiveBuildingPlan` 的本地写入只允许用于 plan 预览，且与 selectedPlanId 同源。
- **Recommended fix**（不在本轮实施）：`setActiveBuildingPlan()` 增加 `demoGuard`；demo 模式下改为先 `demoStore.selectPlan(planId)`（或直接禁用该本地切换），View 层统一走「selectedPlanId ← fireStore 预览」的单一入口；`confirmEvacuationPlan` 必须以 `demoStore.selectedPlanId` 为准并在为 null 时明确提示，不隐式回退到 snapshot 的 recommended。
- **Next batch**：B3-05（本轮之后的补丁批次）

**复现（只读探针，实测数据）**
```
点选 PLAN-C 后：fireStore.activeBuildingPlanId = 'PLAN-C'
                demoStore.selectedPlanId       = null
                demoStore.activeBuildingPlanId = 'PLAN-A'
触发确认后：   backend activeBuildingPlanId    = 'PLAN-A'   ← 与 UI 显示不一致
```

### P1-01 · persons / devices 集合为「本地种子 + 后端按 id 合并」双源
- **Severity**：P1
- **File**：`src/stores/fireStore.js:434-443`（`applyDemoPersons` / 设备合并）、`src/stores/demoStore.js:124-130`；`worker/src/durable/DemoRoom.ts`（只下发当前演练楼栋的运行时对象）
- **Line**：fireStore.js:434、436-443、501-510
- **Current behavior**：`applyDemoSnapshot` 只对 **后端下发 id 存在**的人员/设备做合并；fireStore.persons 共有 220 条，后端运行时只覆盖其中 89 条（当前演练楼栋 B003 的动态人群），其余 131 条（其他楼栋 + static 人群）永远停留在种子初值，devices 同理（每栋 138 台，仅 B003 参与演练）。
- **Why it is a problem**：业务对象列表本身有两套来源且不做「后端未下发 = 未知/离线」标记，导致：① 统计口径（人员态势 220 人）混入了非权威来源的数据；② 一旦某个人/设备因为 id 不一致而漏合并，前端会长期显示过期状态且无冲突信号。当前数据一致，不会立即出错，属于典型的第二套数据源风险。
- **Authority expected**：demo 模式下演习参与对象应以 demo 快照下发的 id 集合为准；非参与对象应显式标记为「非演习对象」并在统计上分层，而不是与动态对象混在同一张无分层列表里。
- **Recommended fix**：快照合并时记录 backend id 集合（`runtimeIds`），UI 统计分「演习对象 / 非演习对象」两层；或在 demo 模式下把未参与对象标识为 `unmanaged:true`。
- **Next batch**：B3-05（与 P0-01 同批评估）

### P1-02 · 3D 方案刷新依赖 `activeRoutePlanId` 的隐式同步
- **Severity**：P1
- **File**：`src/components/BuildingDigitalTwin.vue:166-184`；`src/stores/fireStore.js:2749-2766 / 2641+`（`syncLegacyRouteState`）
- **Line**：BuildingDigitalTwin.vue:179-184
- **Current behavior**：3D 没有直接 watch `store.activeBuildingPlan / activeBuildingPlanId`，而是 watch `store.routePlans`（deep）与 `store.activeRoutePlanId`。这两者是 legacy 投影产物，只有当 `setActiveBuildingPlan → syncLegacyRouteState` 顺带更新它们时 3D 才会跟随。
- **Why it is a problem**：方案切换的 3D 跟随依赖一条隐式副作用链；一旦某条路径只更新 `activeBuildingPlanId`（例如未来直连 demo 快照的分支），3D 人员/路线不会跟随，形成 2D 已换线、3D 仍走旧线的隐性不一致。当前路径可用，故列 P1。
- **Authority expected**：3D 应当直接消费 `activeBuildingPlan`（与 `RouteLayer3D.update` / `PersonLayer3D._resolveRoute` 一样），不再依赖 legacy 投影字段。
- **Recommended fix**：在 `BuildingDigitalTwin` 增加 `watch(() => store.activeBuildingPlan, () => { route.update(store); persons.update(store) })`，并把现有 activeRoutePlanId watch 降级为兼容。
- **Next batch**：B4（3D 批次）

## 8. 明确结论

**PASS WITH P1 FOLLOW-UP**

理由：
- 权威链主链路（Backend → WS → demoStore → fireStore → 2D/3D）为单一权威，`RESET` 后六层全部收敛；2D ↔ 3D 完全一致；B2 / B3 边界无回归。
- 但存在 **1 条 P0**（方案选择双写 → 后端执行与前端显示不一致，同时是 B1 Demo Guard 的唯一漏点）与 **2 条 P1**，因此需要紧接一个最小修复批次（建议编号 B3-05）处理 P0-01 / P1-01，P1-02 并入 B4（3D）。
- 未触发 BLOCKED：没有「后端与前端持续 divergent 且无法恢复」的场景；B4/B5 相关问题均已在批次隔离范围内记录为 P2。

建议的下一批次范围（仅供决策，本轮不实施）：
1. **B3-05（最小补丁）**：`setActiveBuildingPlan` 加 Demo Guard + 方案选择唯一落点 `demoStore.selectedPlanId` + 确认时不隐式回退 recommended；补 `test:e2e:b3e`（点选 PLAN-C → CONFIRM_ROUTE 后 `activeBuildingPlanId === selectedPlanId === PLAN-C`）。
2. **B4**：`LightingView` / lighting 数据源、`RouteLayer3D` dispose、`__dtwin` 卸载清理、`BuildingDigitalTwin` plan watch。
