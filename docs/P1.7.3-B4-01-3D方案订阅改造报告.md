## 3. P1-02 root cause

审计对象：`BuildingDigitalTwin` 的 watcher、`RouteLayer3D`、`PersonLayer3D` 的 plan 变更链路。

**数据读取侧其实早已正确**：

* `RouteLayer3D.update()`：`const bp = store.activeBuildingPlan` → 有整栋楼方案时用它渲染
  （legacy 分支只在 `bp` 为空且存在旧 `routePlans` 时兜底）；
* `PersonLayer3D._resolveRoute()`：优先级 ① 后端 routePoints → ② mock `_evac` → ③ `activeBuildingPlan`。

**问题在触发侧**（修复前的 `BuildingDigitalTwin.vue`）：

```179:184:src/components/BuildingDigitalTwin.vue
watch(() => store.routePlans, () => { route && route.update(store); persons && persons.update(store) }, { deep: true })
watch(() => store.activeRoutePlanId, () => { route && route.update(store); persons && persons.update(store) })
```

即：**没有任何 watcher 订阅 `activeBuildingPlan` / `activeBuildingPlanId`**。

3D 之所以看起来「也会跟着换方案」，完全是 `applyBuildingPlanSelection → syncLegacyRouteState` 的**同步副作用**
把 `routePlans`、`activeRoutePlanId` 顺手改了才触发刷新 —— 这正是 B3-04 / B3-05 记下的隐式依赖：
**3D 是否更新取决于 legacy 投影有没有跟着动，而不是取决于权威方案本身。**

副产物：一旦方案只在 `activeBuildingPlan` 上变化（legacy 投影不变 / 未重算 / 未来任何跳 legacy 的写入路径），
`RouteLayer3D` 会停在旧方案的 tube 上 —— 它不像 `PersonLayer3D` 那样每帧重算路线 key，所以不会自愈。

**负面基线证据**（修复前跑本次专项，同一环境）：

```
T2 ✗ → {"to":"PLAN-A","before3d":"PLAN-C:24","after3d":"PLAN-C:24"}
```

legacy 冻结、`activeBuildingPlan` 已切到 PLAN-A，3D 仍停在 PLAN-C。

## 4. P1-02 fix

```
修复前（触发依赖副作用）
  activeBuildingPlanId ──► syncLegacyRouteState ──► routePlans / activeRoutePlanId ──► 3D update
                              ▲ 只要这段投影没重算，3D 就不更新

修复后（触发直接来自权威）
  activeBuildingPlanId / activeBuildingPlan ──► BuildingDigitalTwin.watch ──► route.update / persons.update
  activeRoutePlanId ─────────────────────────► （仅当没有 activeBuildingPlan 时的 legacy 兜底刷新）
```

落地三条：

1. **权威订阅**：`BuildingDigitalTwin` 直接 watch `[activeBuildingPlanId, activeBuildingPlan]`
   （同时看 id 与方案对象：后端快照重建 plan 对象时也能触发；`RouteLayer3D` 内部按 `planId:routesN`
   指纹去重，不会重复建管）。
2. **legacy 降级**：`activeRoutePlanId` 的 watcher 只在 `!store.activeBuildingPlan` 时生效。
   字段本身保留兼容（未删除、未改 fireStore），但**不再是 3D 方案切换的权威触发源**；
   它仍服务于「无整栋楼方案」的旧单路线渲染（mock / legacy 分支）。
3. **空方案即空指纹**：`RouteLayer3D` 在无 `bp` 且无 `routePlans` 时把 `currentPlanId` 置 `null`，
   使 RESET / 新一轮前 3D 的「当前方案」语义与 fireStore 一致（`group.visible=false` 行为未变；
   tube 的 dispose 仍留给既有 P2-01，本批不动）。
