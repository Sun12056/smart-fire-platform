本轮真正修复的 5 个缺陷：

1. **demo 模式存在两套位置来源**：`fireStore.startEvacuationRun()` 先本地写 `p.routeId` / `p.status='evacuating'` / `p._evac`，再判断 `dataSource.isDemo` 返回 —— demo 下仍有本地模拟抢占。
   → 守卫前置：demo 模式在写任何本地运行态之前直接返回。
2. **PersonView 自己重算坐标**：`projectToZone()` 把人员坐标按「20~80 雷达局部值」归一化，而权威坐标是 `floorPlanData` 的 **560×300** 平面图坐标 → `(x-20)/60` 全部饱和为 1，人员全部堆在区域矩形右下角，且与 DashboardView / 3D 不同源。
   → 改为单向只读的「视图坐标变换」（与 3D 的 `svgToStand` 同性质），输入只来自 `positionOf(p)`。
3. **2D 普遍用旧别名当身份**：`building / floor / area` 参杂在空间判定里（DashboardView 6 处、BuildingView、EvacuationView、RoutePlanView、PersonView）。
   → 统一走新增的 `personInLocation / countPersonsInLocation`（`buildingId/floorId/zone` 优先，旧别名仅回退）。
4. **IDLE 复位不清本地模拟态**：`_evac / _evacDone` 残留，3D 路线优先级②会继续走本地模拟线。
   → 复位分支一并 delete。
5. **冲突输入下旧别名反向成为权威**：`normalizePersonRuntime({buildingId:'B003', building:'1号楼'})` 会把 `building='1号楼'` 原样保留，形成第二套房身份。
   → 别名一律由统一字段派生：`building = BUILDING_ID_TO_NAME[buildingId] || ...`。

顺带清掉只读无写入的幽灵字段 `p._hide`（全仓已无引用）。

## 二、人员字段统一结果

统一契约（唯一权威，9 项 + 运行时标志）：

```js
{
  id, buildingId, floorId, zone, status,
  routeId, routePoints,          // 后端规划产物
  progress, position,            // 后端推演产物
  movementType, waypoint, route, evacuating, retained, rescued,   // 运行时标志（透传）
  building, floor, area, x, y    // 旧别名：只读派生，禁止反向写回
}
```

字段映射（全项目统一口径）：

| 含义 | 权威字段 | 旧别名（只读兼容） | 判定 helper |
|---|---|---|---|
| 人员身份 | `id` | — | map / Set 按 `String(id)` |
| 楼栋 | `buildingId` | `building`（中文名） | `buildingIdOf` / `BUILDING_NAME_TO_ID` |
| 楼层 | `floorId` | `floor` | `floorIdOf` |
| 区域 | `zone` | `area` | `zoneOf` |
| 平面位置 | `position {x,y}` | `x / y` | `positionOf`（始终同源） |
| 路线 | `routeId` + `routePoints` | — | `routeIdOf` / `routePointsOf` |
| 进度 | `progress`（0~1） | — | `progressOf`（越界收敛） |

新增：`personInLocation(p, loc)`、`countPersonsInLocation(list, loc)` —— 空间身份的**唯一口径**，2D 各视图共用，避免每个视图各写一套过滤。

约束（已在 `shared/person/personRuntime.js` 落注释）：
- `progress` 恒收敛到 `[0,1]`；
- `routeId` 只能是后端`/`整栋楼方案产出的 id（`${planId}:${floorId}:${zone}`）；
- 缺坐标时 `position = null`，**禁止编造**。

## 三、后端 → WebSocket → Store → 2D → 3D 数据链

```
worker/src/demo/engine.ts  tickWorld()          ← 后端唯一权威推演（位置/进度/状态）
        ↓ PersonRuntime
DemoRoom.personDTOs()  normalizePersonRuntime   ← snapshot 与 tick 共用同一序列化
        ↓
WS  demo.snapshot / demo.stage / demo.tick      ← 人员字段集合逐字一致
        ↓
demoStore.js:103/125  normalizePersonRuntime    ← 不改 id、不改 routeId
        ↓  applyDemoSnapshot / applyDemoTick
fireStore.js  applyDemoPersons → assignPersonRuntime
        ↓  store.persons（同一批 id、同一份 routeId/routePoints/progress/position/status）
   ┌────┴─────┐
  2D         3D
```

- **2D**：DashboardView（`getPersonsForFloor`）、PersonView（`currentFloorPersons`）读同一份 `store.persons`；
  PersonView 额外做一次**单向视图坐标变换**（平面图 560×300 → 本页版式），输入只有 `positionOf(p)`，不回写 store、不算路线/速度。
- **2D 的 `_evac`**：只剩 mock 路径存在。demo 模式下 `startEvacuationRun()` 提前 return，`_evac` 不会被创建；IDLE 复位还会清空残留。
- **3D 允许 / 禁止**（`PersonLayer3D.js`）：
  - ✅ 视觉插值：`cur.lerp(target, α)`（帧率无关）；路线来源指纹 `backend: / bp: / mock: / none:` 三类
  - ❌ 生成路线：`_resolveRoute` 三选一（后端 routePoints → mock `_evac` → 整栋楼方案预览），没有任何自造途径
  - ❌ 决定速度：无速度概念，位置目标点由权威 `progress` 沿权威折线求弧长得到
  - ❌ 改 status / routeId / progress：`tick()` 每帧从 fireStore 单向同步（`:262-264`），3D 从不反向写
  - ❌ demo 模式误用 mock 运行态：新增 `_mockRuntime(store, p)`，`store.demoMode` 为真时忽略 `p._evac`

## 六、未处理问题（只记录，不在本任务改）

1. **PersonView 的房间版式与平面图坐标系不是同一套**：`FLOOR_LAYOUTS`（viewBox 800×420）与 `floorPlanData`（560×300）各自定义房间矩形。本轮只把「错误的 20~80 归一化」换成单向整体等比变换，房间矩形仍未由平面图派生 —— 建议下一轮让 `FLOOR_LAYOUTS` 直接由 `floorPlanData` 生成。
2. **2D 渲染仍有密度裁剪**：`getPersonsForFloor` 保留 `slice(0, 10/14)`（只影响同屏点位数量，不影响数据链一致性）。
3. **`movementType` 的 'static'/'moving' 语义未与 status 空间对齐**（mock 还把 `static` 当 status 用），建议与 P1.6.2 一并清理。
4. **设备侧仍是旧别名**：EvacuationView / RoutePlanView 读 `dev.building / dev.floor / dev.area`，属 P1.6.2 设备数据链，本轮未动。
5. **`routeMatrix.perZone` 只读兼容投影仍在 fireStore 中**，作为 2D 绘线的回落路径存在，后续应随旧结构一起删除。
6. **环境问题（非本次改动）**：推断演示中途退出会在本地 `wrangler dev` 留下未取消的 Durable Object alarm，`worker/e2e-*` 全部跑完之后复现了 `Workers runtime crashed ... restart (crash #n)` 循环，导致后端无法再响应 —— 上述所有测试均在该现象出现之前完成。恢复方式：清理本地 `worker/.wrangler/state` 后重启 `wrangler dev`（当前沙箱的安全删除拒绝了 rm 操作，未代劳）。
