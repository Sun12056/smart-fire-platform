## 2. 根因与实际修复方案

### 任务 A — 规则乙（对称拐角）

**根因**：`routeDirectionAtDevice` 用最近节点的**中心差分** `next.x − prev.x` 推导方向。在「入边水平 + 出边垂直」的拐角处，中心差分的水平分量**全部来自入边**（设备身后那段走廊）；而设备实际已位于走廊端头→楼梯的**竖向引入段**上。

实测（真实拓扑）：

| 设备 | 最近节点 | 入边 | 出边 | 设备垂距 | 中心差分实际来源 |
|---|---|---|---|---|---|
| EL-5F-01 (72,162) | `CORRIDOR_W`(72,170) | `CORRIDOR_N→CORRIDOR_W` dx=−68（水平） | `CORRIDOR_W→STAIR_NW` dx=0（垂直） | **0**（落在出边上） | 全部来自入边 |
| EL-5F-13 (477,162) | `CORRIDOR_E`(477,170) | `CORRIDOR_S→CORRIDOR_E` dx=+62（水平） | `CORRIDOR_E→STAIR_NE` dx=0（垂直） | **0**（落在出边上） | 全部来自入边 |

现有数据无法区分走廊指示与楼梯指示（设备无安装/朝向/指示类型字段，`area` 标为"走廊"但几何在楼梯引入段上）⇒ 按 Q1 采用规则乙：不输出 `left/right`，保守返回 `undetermined`。

**修复**：在 `cornerOrReversalReason()` 中新增对称分支 ④：

```js
if (inHorizontal && !outHorizontal) {
  const on = pointSegmentDistance(devX, devY, cur.x, cur.y, next.x, next.y)
  if (on.distance <= CORNER_ON_EDGE_EPS) return 'corner-vertical-out-edge'
}
```

配套：被判为不可靠时 `dx` 归零（原始中心差分保留在 `dxCentered` 供审计）；`resolveDeviceDirections` 记入 `undetermined` 而非 `bindings`。

**遵守的约束**：
- 降级条件仍是「**确认**设备落在该垂直边上」（垂距 ≤ `CORNER_ON_EDGE_EPS` = 1e-6），不做模糊阈值猜测；
- 已有 `corner-vertical-in-edge`、`direction-reversal-at-node`、`no-horizontal-movement` 语义全部保留；
- 未使用路线权重 / `personCount` / 拥堵 / 字典序选边（有专项测试）；
- 未切换为线段投影方案（第二轮的 9/11 退化结论仍有效，本轮未重构）；
- 未改建筑拓扑，未引入关联距离阈值（Q4 / Q5）；
- 未新增设备字段或协议字段（Q3）。

### 任务 B — 无效状态不得显示带朝向的箭头

**根因**：`EvacuationView.vue` 中无效状态只是给同一个箭头加 `opacity: 0.22 + grayscale(1)`（`arrow-invalid`），而**旋转角 `currentAngle` 由 `watch(() => evacStore.currentDevice?.direction, { immediate: true })` 驱动** —— 即箭头虽然变暗，仍**指向历史方向**。这违反"不要用透明度/灰度/删除线表示无效"的要求。

**修复**：
1. 模板改为 `v-if / v-else`：
   - `v-if="directionDisplay.showArrow"` → 渲染带朝向的箭头（仅 `resolved` / `overridden`）；
   - `v-else` → 渲染**无方向性占位图形**（虚线圆环 + 居中短横，左右完全对称）+ 文案「无有效方向」。
2. `currentAngle` 的 watch 源改为 `directionDisplay.value.direction`，不再读设备历史 `direction`。
3. 方向键 `active` 统一改为**只**由 `directionDisplay.direction` 决定；`unverified` 改为 `!directionDisplay.showArrow`，与箭头可见性同源 —— 无效状态时两个键都不高亮。
4. 方向文字恒由 `directionDisplay.direction` 决定，无效时显示 `—`（`currentDirectionLabel`）。
5. 删除 `.dir-text.dir-stale` 的删除线（`—` 上划删除线是无意义噪声，且删除线本质上仍是"弱化样式"）。
6. 历史字段全部保留：`storedDirectionLabel`、`overrideSourceLabel`、设备 `direction` 均未删除，只在提示中作为"旧值"展示。

- 本仓库测试架构**不挂载 Vue 组件**（`EvacuationView` 依赖 Pinia / Element Plus / 路由），因此**没有**组件渲染或浏览器 E2E 证据。源码级断言只能证明"模板结构正确"，不能证明"渲染结果正确"。

- `overridden` 状态仍渲染带朝向的箭头 —— 这是 Q2 允许的（本地覆盖是明确设定），并配「本机覆盖（非本轮路线裁决）：管理员手动切换，未下发设备」提示。
