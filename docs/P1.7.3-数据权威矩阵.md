# P1.7.3 数据权威矩阵

> 审计范围：`Backend(DemoRoom/engine) → WebSocket → demoStore → fireStore → 2D → 3D`
> 本轮**只审计、不改代码**。所有结论均带 `文件:行` 证据，行号对应当前 `main`（`9414caa`）。
> 核心原则：**后端是业务状态权威来源，前端 Store 是状态镜像，2D/3D 是同一份状态的不同可视化。**

## 六、权威矩阵的最终判读

1. **权威点唯一**：8 类数据的权威写入点全部可枚举且落在后端，无「两个后端同时权威」的情况。
2. **镜像层存在第二条写路径**：`fireStore` 的 6 条本地写 demo 业务状态的通道（C1/C3/C5）+ `LightingView` 的 UI 直写，是当前「一致性」最大的破坏面。
3. **2D/3D 同源已基本成立**：二者均消费 `fireStore.persons / fireEvent / devices / activeBuildingPlan`，差异仅存在于：3D 只吃 `emergencyMode` 布尔（`EmergencyLight3D.js:144`）、以及 3D 的人员出现 **2.2s 错峰 + 抵达缩放** 视觉延迟（`PersonLayer3D.js:298,315`）。
4. 修复方向建议：**补守卫**（让本地写路径在 `dataSource.isDemo` 下不可达），而非重写数据流。
