## 2. 关键调用链

```
后端（唯一持有方，D-1=B）
  createWorld()                       engine.ts        exits = defaultExitStates()   ← 静态权威定义
  DemoRoom.loadWorld()                DemoRoom.ts      旧 world 无 exits → 补全      ← 恢复机制
  snapshot()                          DemoRoom.ts      exits: world.exits            ← 随快照下发
        │
        ├─ 路径 A：planBuildingStrategies({ exits: world.exits })   engine.ts:ROUTE_PLANNING
        │      └─ planBuildingEvacuation → planZoneRoutes → fireBlockSets → findPaths → isExitUsable ✅
        └─ 路径 B：planEvacuationRoutes({ exits: world.exits })     engine.ts（legacyPlans）
               └─ findPaths → isExitUsable ✅（生成/落库/快照/LEGACY REST 兼容全部保留，D-2=A）

前端（消费方）
  demoStore.applySnapshot → fireStore.applyDemoSnapshot
        └─ ⑨ applyExitRuntimeStates(snap.exits)   ← 缺失/过期 → 回落静态默认 + degraded 标志（不静默）
        └─ invalidateRoutesWithUnusableExit()    ← 目标 6：存量路线失效
  路径 C generateRoutePlans：exitIdsOf(...) → usableExitsOf(...)   ← 按运行态筛选
  路径 D replanRoutesForFire：同上 + validateRoute 补齐（D-5=A）
```

**出口状态缺失 / 过期的处理**（D-1 明确要求）：

| 情形 | 处理 | 是否静默 |
| --- | --- | --- |
| `undefined` / `null` / `[]` | 回落到静态权威定义（全 OPEN），`degraded=true`、`reason='missing'` | 否，`console.warn` 显式告警 |
| 结构非法（无 nodeId 等） | 同上，`reason='invalid'` | 否 |
| 部分下发 | 未列出的出口按静态默认补全，`reason='partial'` | 否 |
| 单个出口缺 `available` | 判为 `false`（不可用） | — |
| 单个出口缺 / 非法 `status` | 判为 `CLOSED`（不可用） | — |
| 陈旧运行态 | **不使用**陈旧值，回落静态默认 | 否 |

原则：任何不确定一律判为**不可用**（fail-safe）；不使用陈旧运行态，因为陈旧状态可能把已关闭出口误报为可用。

## 5. 实施过程中发现并修复的两个真实缺陷

1. **DO 恢复机制缺失**：`DemoRoom.loadWorld()` 从 DO storage 恢复的旧 world 没有 `exits` 字段 → 快照下发 `undefined`，前端只能降级（违背"后端唯一权威"）。已补全。
2. **失效判定漏掉本地路线**：路径 C/D 产出的 plan 用 `exit` 字段，而后端方案投影用 `exitId`；`invalidateRoutesWithUnusableExit` 最初只认 `exitId` → 本地生成的存量路线**漏网**。已兼容两者。

两者均由四路径运行时验证暴露（单测无法发现），印证了"不得只用底层单测代替端到端证据"。

## 6. 遗留限制

1. **路径 D 未在浏览器端运行时触发**：demo 模式下 `activeBuildingPlan` 恒存在，`replanRoutesForFire` 在 `:3069` 提前返回。其出口过滤与 `validateRoute` 补齐已落地并通过代码核实，但**运行时证据缺失**，属低可达分支。
2. **两套火灾割集仍未统一（D-4=A）**：规划器 `blockedNodesForFire` vs 前端 `blockedNodeIds`（自行推导的"推荐路线 ±N 段"膨胀）**不同源**。本阶段已测试"出口过滤与现有火灾阻断可同时生效"，但**不得宣称两套割集已一致**。
3. **无运行时改变出口状态的入口（D-6=A）**：出口状态目前恒为静态默认（全 OPEN），因未接外部源，e2e 中只能通过页面注入验证过滤逻辑，**无法验证"真实的运行中关闭"场景**。
4. **`capacity` 仍无业务含义（D-7=A）**：恒为 `null`，未定义单位 / 口径 / 超载策略。
5. **Worker 侧无 TS 静态类型校验**：仓库未安装 `typescript`（既有状态，未安装依赖以防改动依赖），TS 改动仅经 e2e 运行时验证。
6. **路径 A/B 的"非默认状态过滤"仅有单测证据**：因限制 3，无法在 e2e 中让后端持有非默认出口状态。
7. **存量落库的 LEGACY REST 行**：`legacyPlans` 落库行为保留（D-2=A）；出口关闭后旧行不会自动删除，仅在新一轮重规划时按 id `REPLACE` 覆盖。历史行的"当前有效性"由前端标记而非库内标记。
