> 火灾只作为动态障碍，不再决定「谁参与疏散」。

## 三、数据结构

```jsonc
BuildingEvacuationPlan {
  id: "PLAN-A",                 // PLAN-A / PLAN-B / PLAN-C
  name: "方案A·均衡疏散",
  buildingId: "B003", buildingName: "3号楼",
  scope: "BUILDING",            // 恒为 BUILDING，与火灾位置分离
  strategy: "BALANCED",         // A=BALANCED 均衡 / B=FASTEST 快速 / C=SAFEST 安全
  fire: { buildingId, floorId, zone },   // 只描述火灾位置
  summary: { zoneCount, routeCount, validRouteCount, personCount, floors[], exits{},
             exitLabels[], totalDistance, maxEstimatedTime, avgEstimatedTime,
             riskLevel, stairRouteCount },
  routes: [ EvacuationRoute ],  // 每个「有人员的 floorId+zone」一条
  routesByZone: { "5F:A区": EvacuationRoute }
}

EvacuationRoute {
  routeId: "PLAN-A:5F:A区",     // 后端下发与前端 2D/3D 消费同一个 id
  floorId, zone, startNode, exitId, exitLabel,
  nodes[], points[], distance, estimatedTime, riskLevel,
  valid, reasons[], floorsPassed[], personCount, sourcePlanId
}
```

**策略语义（整栋楼级别，不再是某区域的三条路线）**
- A `BALANCED`：综合评分 + **出口负载均衡**（把人流分摊到不同安全出口）
- B `FASTEST`：每个区域取预计耗时最短的路线
- C `SAFEST`：风险最低 / 离火源最远

**规划流程**
```
整栋楼人员 → groupPersonsByZone（floorId + zone）
           → 每组调用现有 findPaths()（Dijkstra / Yen 未改动）
           → pickRouteByStrategy 选一条
           → routeFromCandidate → BuildingEvacuationPlan
           → validateBuildingEvacuationPlan（逐条复用 validateRoute）
```
- 每条路线：不穿墙、不经过 `blockedNodes`（火区）、终点必须是 `1F:EXIT_*`、跨层必经楼梯
- `走廊` 等公共区域没有房间节点 → `resolvePlanningZone()` 按最近房间节点归属，保证人人有合法起点（**未修改 routeGraph 拓扑**）

## 五、遗留问题

1. **停用楼梯未迁移**：`FLOOR_CONFIG.stairsActive`（3F/4F/6F 停用）在 shared 拓扑中无对应，按指令 16 未动；迁移需给 shared 增加 per-floor 楼梯黑名单。
2. **走廊人员归属是近似**：`resolvePlanningZone` 按最近房间节点归属，不是真实语义；P2 可考虑走廊专用起点或按门最近原则。
3. **旧结构并存**：`world.plans`（火源区 A/B/C）与 `buildingPlans` 同时存在、同时落 D1，旧接口 `/api/v1/evacuation-plans` 会返回两类记录；前端 `routeMatrix.perZone` 仍按「当前查看楼层」派生，属过渡兼容层，后续应删除。
4. **整栋楼基线改动面较大**：DemoRoom 基线从「火警楼层」改为「整栋楼」（`BASELINE_KEY` 升到 `baseline.v2`），联动设备也改为整栋楼，需观察只关注 5F 的页面表现。
5. **DemoPanel/Dashboard 的方案卡片**：上方已加整栋楼策略 chips（A/B/C + 区域数/人数/最慢耗时），下方旧卡片仍是「该区域在三种策略下的路线」，未完全合并。
6. **滞留人员（P2 未做）**：仍是随机取 2 人，未做 `retainedCandidates` 预置人选；候选池已从火警楼层扩展到全楼未完成人员。
7. **mock 模式跨层动画未验证**：2D 平面图按楼层展示，跨楼层下降只在 3D 体现，mock 模式无后端 routePoints，未做等价验证。
