## 五、`invalidDirection` 的唯一定义（技术歧义裁决建议）

**结论：它是「可显示状态的方向校验失败」标记，不是「任意状态的非法载荷」标记。**

### 5.1 定义（唯一）

```
可显示状态集合 displayableState =
    state ∈ { resolved, remote }
  ∨ (state === 'overridden' ∧ overrideSource === 'manual')

invalidDirection === true
  当且仅当  displayableState === true  且  白名单校验未产出合法方向
```

### 5.2 为什么不是「任意状态」

1. 不可显示状态（`conflict` / `undetermined` / `unlinked` / `none` / `overridden(fire-avoidance)` / `overridden(未知来源)`）的 `direction` **从不被读取、从不被输出**，对其置位只会产生无法被 UI 与测试赋予含义的噪声；
2. 若两者都置位，测试将无法区分「脏载荷」与「正常降级」，`assert` 会退化为「反正一律 true」；
3. 与既有 `stale` 的分工会被打乱：`stale` 表达「有历史值但本轮无效」，`invalidDirection` 表达「本轮裁决载荷本身坏了」——两者语义不同，不能混同。

### 5.3 与实现的对应（便于测试与 UI 对齐）

| 组合 | `direction` | `showArrow` | `invalidDirection` | `stale`（有合法历史值时） |
|---|---|---|---|---|
| `resolved` + 合法 | `left/right` | true | false | false |
| `resolved` + 非法/缺失 | null | false | **true** | true |
| `remote` + 合法 | `left/right` | true | false | false |
| `remote` + 非法/缺失 | null | false | **true** | true |
| `overridden(manual)` + 合法 | `left/right` | true | false | false |
| `overridden(manual)` + 非法/缺失 | null | false | **true** | true |
| `overridden(fire-avoidance)` / 未知来源 | null | false | **false** | true |
| `conflict` / `undetermined` / `unlinked` / `none` / 未知 state | null | false | **false** | true（若有合法历史值） |

### 5.4 UI 与测试的使用边界（不扩大范围）

- **UI**：本批**不新增任何**基于 `invalidDirection` 的文案分支（避免范围扩张）；界面表现就是「无箭头 + 有历史值时 `stale` 提示」。
- **测试**：作为纯函数断言与脏数据定位字段（U5 用例：`resolved` + `'up'` ⇒ `invalidDirection=true`）。
- **实施时须同步修正**《修订版》§4.4 表格中「任何 state」的措辞为：「**校验对所有 state 执行（决定方向是否可用），但 `invalidDirection` 仅对可显示状态置位**」。
