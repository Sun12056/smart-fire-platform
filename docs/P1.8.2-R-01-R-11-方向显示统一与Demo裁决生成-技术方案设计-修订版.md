## 4. 统一 resolver（本版核心修订）

### 4.1 唯一判定入口（签名不变）

`resolveDirectionDisplay(verdict, storedDirection)` —— 入参形状与调用方式**不变**，行为按下表收紧。所有显示面只能由此函数得到「是否画箭头 / 画哪个朝向」。

### 4.2 状态与标志的严格语义

| 输出字段 | v1 | **本版（修订）** | 依据 |
|---|---|---|---|
| `direction` | `resolved \|\| remote \|\| overridden` 时取 `verdict.direction` | 先过 §4.4 白名单；仅 `resolved` / `remote` / `overridden(manual)` 且方向合法时输出 `'left'\|'right'`，否则 `null` | 修正 #1 #4 |
| `showArrow` | `!!direction` | `!!direction`（不变式保持） | — |
| `isValidRouteGuidance` | `state === 'resolved'` | 不变 | — |
| `isRemoteGuidance` | 新增 | 不变（`state === 'remote'`） | — |
| `isManualOverride` | `state === 'overridden'` | **`state === 'overridden' && overrideSource === 'manual'`** | **修正 #1** |
| `isOverridden` | — | **新增**：`state === 'overridden'`（表达「存在本机覆盖」这一事实，与「是否人工设定」解耦） | 修正 #1 的配套 |
| `overrideSource` | — | **新增透出**：`verdict.overrideSource \|\| null`（供 UI 无条件显示来源，无需回读 verdict） | 修正 #2 |
| `stale` | `!resolved && !override && !!stored` | **`!showArrow && storedDirection !== null`** | 修正 #4（见下） |
| `storedDirection` | `storedDirection \|\| null` | **仅当通过白名单时输出，否则 `null`**（非法历史值不得进入 UI） | 修正 #4 |
| `hasStoredButUnverified` | `!!stored && !isResolved` | `!!storedDirection && !isResolved && !isRemote`（全仓无消费者，保持为审计字段） | — |
| `invalidDirection` | — | **新增**：`true` 表示「state 本应可显示，但 direction 未过白名单」⇒ 审计用 | 修正 #4 |

**`stale` 重定义的理由**：原式在「state 可显示但方向非法」时给出 `stale=false`，界面会既无箭头也无提示（静默）。新式 `!showArrow && 有合法历史值` 保证「无箭头 ⇒ 要么无历史值（无需提示），要么一定有提示」。

### 4.3 覆盖来源：单一映射 + 单一解析函数（Q1 = 甲）

```js
DIRECTION_OVERRIDE_SOURCE_LABELS = {
  manual: '管理员手动切换，未下发设备',
  'fire-avoidance': '避火自动反向，非路线裁决',
  unknown: '未知覆盖来源（不作有效指引）',
}
overrideSourceLabelOf(source)  // 未命中 ⇒ DIRECTION_OVERRIDE_SOURCE_LABELS.unknown
```

| source | 是否显示方向箭头 | UI 必须显示的来源文案 | 理由 |
|---|---|---|---|
| `manual` | **是** | 「管理员手动切换，未下发设备」 | 值是管理员显式设定的 `left/right`，不依赖旧值 |
| `fire-avoidance` | **否**（Q1 = 甲） | **「避火自动反向，非路线裁决」必须显示** | 方向 = `flip(旧值)`，输入可能是从未裁决过的种子值；显示即等于「陈值洗白」（R-08） |
| 未知来源（含未来新增、`undefined`） | **否** | 「未知覆盖来源（不作有效指引）」 | 默认拒绝；**禁止**回退成原始字符串（v1 的 `labels[src] \|\| src` 会把 `'xxx'` 直接展示给用户） |

**三处消费点统一改走 `overrideSourceLabelOf()`**：`EvacuationView.vue:617-620`、`DashboardView.vue:1788`、`BuildingView` 弹窗新行。`DashboardView.vue:1177` 的 `DIRECTION_OVERRIDE_SOURCE_LABELS` 导入随之改为导入该函数 —— **`DashboardView.direction.test.mjs:58` 的源码级断言需同步改为断言函数名**（已在 §9.4 列出，非放宽断言）。

**`fire-avoidance` 的来源必须可见（Q1 附加要求）**：该状态 `stale=true`，EvacuationView 会命中 `v-if="routeVerdictIsStale"`（`:119`）分支，因此必须在**该分支文案**中拼上 `overrideSourceLabel`；否则界面只剩「保留旧方向」而没有「避火自动反向」这一关键来源。`DashboardView.selectedOverrideNote`（`:1782-1790`）已按 state + source 渲染，无需改逻辑，仅换 label 解析函数。

### 4.4 方向白名单（fail-closed）

```js
DIRECTION_DISPLAY_DOMAIN = Object.freeze(['left', 'right'])
validDisplayDirection(v)  // 严格相等：不 trim、不做大小写归一、不做真值判断
```

校验点与失败动作：

| 输入 | 位置 | 非法时动作 |
|---|---|---|
| `verdict.direction` | resolver 内部，**任何 state** | 不输出方向（`direction=null`、`showArrow=false`、`invalidDirection=true`） |
| `storedDirection`（设备 `dev.direction`） | resolver 内部 | 不作为「历史值」输出（`storedDirection=null`），不参与任何判定，仅使 `stale` 不成立 |
| Demo 投影入参 `r.direction` | `projectDemoDirectionVerdicts()` | 不写 `unsigned`；写 `state='undetermined'`、`reason='backend-direction-invalid'` |
| 路线裁决入参 | 不新增校验 | `resolveDeviceDirections` 只可能产出 `left/right`（`deviceDirection.js:204`），保持不改 |

必要性证据：`deviceRuntime.js:70-74` 的 `directionOf()` 对**任意非空字符串原样返回**（如 `'RIGHT'`、`'up'`、`'left '`），而 `:179-182` 的 `deviceDirection()` 又把所有非 `'left'` 折叠成 `'right'` —— 两者叠加会让非法值在 2D/3D 上被渲染成一个**看似有效**的方向。resolver 是最后一道闸门，必须拒绝。

> 取值域未被扩展：`left`/`right` 仍是唯一合法值，本批只是**把「非法值 → 右侧」的隐式兜底改成「非法值 → 无方向」**。

## 5. Demo 裁决生成契约（R-11，含修正 #6）

### 5.1 权威输入核实（DTO ←→ Store 逐字段）

| 字段 | D1 列 | DemoRoom 映射 | DTO 规范化 | 前端合并 | 投影取值 |
|---|---|---|---|---|---|
| `id` | `devices.id` | `String(r.id)`（`DemoRoom.ts:73`） | `id: String(r.id)`（`deviceRuntime.js:105`） | `dmap` 键 = `String(d.id)`（`fireStore.js:578`） | **`String(d.id)`**（与 store 设备同一键） |
| `type` | `devices.type` | `String(r.type)`（`:74`） | `typeOf()`：非空字符串原样，否则 `''`（`:54-57`） | `assignDeviceRuntime` 仅在 `n.type` 非空时覆盖 `target.type`（`:202`） | **合并后的 `d.type`**（= UI 实际渲染所用类型） |
| `direction` | `devices.direction` | `String(r.direction ?? 'right')`（`:81`） | `directionOf()`：非空字符串原样，否则 `'right'`（`:70-74`） | `applyStrictDeviceRuntime` 整字段覆盖（`:728`） | **`r.direction`（DTO 原始值）** |

**ID 同源证据**：D1 种子由 `worker/src/seed.ts:35` 的 `buildSeedDevices()` 生成；store 设备同样来自 `buildSeedDevices()`（`fireStore.js:107`、`:2688`）⇒ 同一生成器、同一 ID 字面量，按 `String(d.id)` 精确对齐。

**投影的权威输入（三条硬规则）**：

1. **在 `applyDemoSnapshot` 的设备合并循环内收集**（`fireStore.js:583-591` 的 `r` 分支），因此「不在本次快照内的 store 设备」天然不产生条目（对应 `:584-588` 的 `!r` 提前返回路径）；
2. 方向取 **`r.direction`**，不取 `d.direction`。二者在当前链路等价，但 `d.direction` 已经过 `directionOf()` 的 `'right'` 兜底，取 `r` 才符合「投影依据 = 后端下发原值」；
3. 灯具判定取 **`d.type`**（合并后值），因为它是 UI 渲染所用的类型，且 `assignDeviceRuntime` 保证与 `r.type` 一致（除非 DTO 未给）。

**必须如实记录的链路事实（不得在实施报告中夸大）**：`direction` 的缺失在上游**已被折叠两次**（`DemoRoom.ts:81` 的 `?? 'right'` + `deviceRuntime.js:70-74` 的默认值），因此投影中「缺失 ⇒ `undetermined`」分支**在当前生产链路上不可达**，只会命中「非空但不是 `left/right`」的非法值。该分支保留为防御，但验收不得声称「已处理方向缺失」。

### 5.2 生成规则

| 输入（`r` 存在于快照 ∩ store 设备） | 输出条目 |

| `d.type ∈ {'evacuation_light','emergency_light'}` 且 `validDisplayDirection(r.direction)` | `{ deviceId, state: 'remote', direction, source: 'demo-backend' }` |
| 同上，`r.direction` 非空但未过白名单 | `{ deviceId, state: 'undetermined', source: 'demo-backend', reason: 'backend-direction-invalid' }`（Q1/修正 #3 的 fail-closed 落点） |
| 同上，`r.direction` 缺失 / `null` / `''` | 同上，`reason: 'backend-direction-missing'`（**防御分支，当前不可达**，见 §5.1） |

**两个灯型都要覆盖**：`LIGHTING_DEVICE_TYPES`（`deviceRuntime.js:144`）与 b403 的 `isLight()`（`worker/e2e-p173-b403-runtime-unity.cjs:127`）都把两类灯视为灯具，且 2D 的 `data-dir` 写在所有设备节点上。只覆盖 `evacuation_light` 会击穿既有三端一致性断言。

3D 图层的显示结果由**两类彼此独立的状态**共同决定，二者的更新机制完全不同：

| 变化源 | 更新机制 | 影响的视觉 | 本批处理 |
|---|---|---|---|
| ① 裁决表 `routeDirectionVerdicts` | 整表替换（§4.5：7/7 不可变） | 箭头**方向**、箭头/占位**显隐**、`rec.displayState` | 读 `store.directionVerdictIndex`（Vue computed） |
| ② 设备运行态 `dev.*` | **就地变更**（`assignDeviceRuntime` / `applyStrictDeviceRuntime` 直接改字段，数组引用不变） | 亮度、应急脉冲、离线透明；以及 `storedDirection`（影响 `stale`） | `tick` 每帧按 id 重新解析 `dev`（既有 `EmergencyLight3D.js:158-166` 已如此） |

**实现约束（三条）**：

1. `tick` 每帧对每台灯现算 `resolveDirectionDisplay(store.directionVerdictIndex.get(id), dev.direction)`，**禁止缓存「每设备显示结果」** —— 否则 ② 的就地变更会被 ① 的缓存遮挡；
2. 只允许缓存**裁决表索引**，且直接使用 store 的 `directionVerdictIndex`（Vue computed，依赖 `routeDirectionVerdicts` 自动失效），**3D 内不自建引用缓存**（修正 #5：虽然盘点后 7/7 不可变、准入条件已满足，但多一层旁路状态即多一处可能失效的点，本版不引入）；
3. `rec.dir` 语义改为**实际渲染方向**（`'' | 'left' | 'right'`）；新增 `rec.displayState`（七态）与 `rec.verdict`（`{ state, overrideSource }` 快照，每帧刷新）；`_syncRuntime`（`:224-229`）的 `rec.runtime.direction` **保持权威原值不变**（B4-03 五字段契约不动）。

`_bindEvac`（`:99-125`）改为 `_bindEvac(dev, store)`，初值走同一 resolver（不得再用 `dev.direction || 'right'`）；若 `store.directionVerdictIndex` 不存在（防御），按 `null` verdict 处理 ⇒ 无箭头（fail-closed）。

## 7. 覆盖状态处理规则（R-08，含修正 #1 #2）

### 7.1 `overridden` 三问

| 问题 | 结论 |
|---|---|
| 谁写 | `fireStore.js:1517`（批量手动）、`:2987`（单设备手动）、`:1772` / `:2462`（避火自动反向），均经 `markDirectionOverridden`（`:4230-4241`）—— **写点全部保留，不改时机** |
| 依据是否可信 | `manual` 可信（显式人工定值）；`fire-avoidance` 不可信（`flip(旧值)`，输入可能是种子值）；未知来源一律不可信 |
| 能否显示 | 仅 `manual` 显示；其余不显示且**必须显示来源**（§4.3） |

### 7.2 写者 / 优先级矩阵

| 写者 | 生效模式 | 写入方式 | 范围 |
|---|---|---|---|
| `applyRoutesToDevices`（`:4198`） | mock / api | 整表替换 | 本轮全部目标设备 |
| `applyBuildingRoutesToDevices` 全阻分支（`:4112-4114`） | mock / api | 整表清空 | 全部 |
| `projectDemoDirectionVerdicts`（新增） | **demo** | 整表替换 | 快照 ∩ store 内全部灯具 |
| `markDirectionOverridden`（改后） | 两模式 | **整表替换（过滤同 id + 追加）** | 单设备 |
| 清空点 `:264` / `:1590` / `:3808` | 两模式 | 整表清空 | 全部 |

同一时刻只有**一个主写者**（demo 投影 / 路线裁决互斥，由正反向守卫保证）；`overridden` 是次写者，生命周期 ≤ 下一次主写者覆盖。

### 7.3 失效与清除

| 事件 | 动作 |
|---|---|
| 新一轮路线裁决 / 新一次快照 | 整表替换（含「设备已不在快照内 ⇒ 条目消失」） |
| 手动 / 避火改写方向 | 该设备条目 → `overridden`（整表替换实现） |
| 复位 / 清空方案 / 清火 | 整表清空 |
| 路线失效 / 设备离线 / 快照断线 | **不做任何动作**（R-03 / R-04 排除） |

### 7.4 不新增的字段

`expiresAt` / `staleReason` / `deviceOnline` / `routeInvalidated` —— 一律不新增。本批**不使用 `basis` 字段**：来源判定由既有 `overrideSource` 承担（v1 曾考虑 `basis`，本版删除，减少一个可被写错的状态）。
