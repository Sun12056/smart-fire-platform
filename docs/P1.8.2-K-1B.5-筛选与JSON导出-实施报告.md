## 三、筛选规则与缺失状态处理

- 两个维度 AND；任一为「全部」（`''`）则该维度不过滤。
- 状态按路线 `id` 关联 `manualRouteStatusView` 投影（`routeStatusMap`），**不在路线对象上写状态**。
- 缺失状态：`statusOf` 回落 `{ topologyStatus:null, exitStatus:null, … }`；筛选为具体状态时 `null !== 具体值` → 不匹配（排除）；筛选为「全部」→ 保留。
- `BUILDING_UNAVAILABLE` 独立于 `INVALID`，`UNKNOWN` 独立于 `UNAVAILABLE`，未合并、未改变现有状态语义。

## 四、导出 JSON 字段契约与来源

```json
{
  "exportedAt": "2026-10-22T…Z",       // 本次导出时间（ISO 8601）
  "scope": "filtered",                  // 固定
  "totalRoutes": 1,                     // 实际导出条数 == filteredRoutes.length
  "filter": { "topologyStatus": null, "exitStatus": "UNKNOWN" },  // '' 归一为 null
  "routes": [{
    "id": "RP-MANUAL-…", "buildingId": "B003",
    "startNode": "5F:A_CENTER", "exitId": "1F:EXIT_W",
    "nodes": ["…"],                     // ← manualExecutableRoutes
    "topologyStatus": "VALID", "topologyReason": null,   // ← manualRouteStatusView
    "exitStatus": "UNKNOWN",   "exitReason": "NO_EXIT_RUNTIME",
    "routeCreatedAt": 1700000000000,    // 仅当真实存在才导出
    "routeUpdatedAt": 1700000000000
  }]
}
```

- 原始字段（`id/buildingId/startNode/exitId/nodes/createdAt/updatedAt`）来自 `manualExecutableRoutes`；状态字段来自 `manualRouteStatusView`（按 id 关联），导出过程**不重新计算状态**。
- 时间字段仅在真实存在时导出（`routeCreatedAt`/`routeUpdatedAt` 命名与顶层 `exportedAt` 区分，避免把导出时间误当路线更新时间）；`createdAt`/`updatedAt` 确为 `manualExecutableRoutes` 真实字段（K-1B.2 建立）。
- 原因/状态缺失导出 `null`；未知状态字符串保留原值。`JSON.stringify(payload, null, 2)` 原生转义特殊字符。
- 导出走浏览器原生 `Blob + URL.createObjectURL + a.download`，无新依赖；临时 `<a>` 同步移除，对象 URL 延迟 `setTimeout(…, 1000)` 释放，避免过早回收；下载失败不改路线数据/筛选/持久化。
- 空结果不禁用则按钮禁用（不伪造记录）。
