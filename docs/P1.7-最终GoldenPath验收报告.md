## 三、本轮对验收脚本的四处口径修正（均为脚本缺陷，非产品问题）

| # | 现象 | 根因 | 修正 |
| --- | --- | --- | --- |
| 1 | 12–15 步后端不推进 | 6.5 步打开 3D 浮层后未关闭；`.dtwin-modal` 是 `inset:0 / z-index:900` 遮罩，挡住了后续业务按钮 | 采样后点 `.dtwin-modal-close` 关闭浮层 |
| 2 | `确认人员位置` 找不到按钮 | 该按钮由 `v-if=strandedPersons.length` 控制且需在火警楼层面板 | 补等待（4s），未渲染则先「聚焦火区」再等 10s |
| 3 | `GP-12.2 demoStore 未收敛` | REST 已推进但 WS 快照仍在传播窗口内就采样 | REST 达标后再等 demoStore 收敛（≤10s） |
| 4 | RESET 步的「单调不回退」判红 | RESET 本身就是回退到 IDLE，不该套单调性 | RESET 步排除出单调性与阶段序列校验 |

另：3D 火区断言原写为 `fire.visible === !!fireEvent`，实测正确口径是**还要求「当前楼栋 == 火情楼栋」**
（`FireZone3D` 在总览态按设计不显示火区）；并允许 6s 最终一致窗口，期间句柄断开则跳过判定。

## 四、一处真实观察（非阻断，未修）

`COMPLETED` 时 **DemoPanel 末步显示 `processing`，而 `demoStore.flowSteps` 权威投影是全 `done`**：

```
ui = [发现火灾:D, 启动应急响应:D, 疏散路径规划:D, 智能疏散:D, 滞留人员识别:D, 协同消防救援:P]
ds = [发现火灾:D, 启动应急响应:D, 疏散路径规划:D, 智能疏散:D, 滞留人员识别:D, 协同消防救援:D]
```

成因（`src/components/DemoPanel.vue:163-168`）：

```js
function stepStatus(idx) {
  const cur = platformStore.demoStepIndex   // COMPLETED 时 = 5
  if (idx < cur) return 'done'
  if (idx === cur) return 'processing'      // ← 末步被判成 processing
  return 'pending'
}
```

而 `demoStore.flowSteps` 的 done 判据含 `|| stage === 'COMPLETED'`，二者在终态分叉。
**不阻断流程**（后端 COMPLETED、其余七层全部一致），属终态显示瑕疵，与 B-01 同属
「UI 由 `demoStepIndex` 重算而非直接消费权威投影」这一类。

按「Golden Path 只做验收 + 必要阻断性修复、不扩大范围」的约束，**本轮未改**，
建议与 P2-02 一起单开一批处理（一行级改动：`stepStatus` 增加 COMPLETED 覆盖）。
