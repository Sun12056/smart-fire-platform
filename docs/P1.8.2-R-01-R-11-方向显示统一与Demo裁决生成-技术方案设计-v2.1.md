## 4. 统一 resolver

### 4.1 唯一入口（签名不变）

`resolveDirectionDisplay(verdict, storedDirection)`。所有显示面只能由此得到「是否画箭头 / 画哪个朝向」。**入参形状与调用方式不变**，避免波及既有 3 个消费方与 2 个测试文件。

| 字段 | 语义（v2.1） |
|---|---|
| `direction` | 仅 `displayableState` 且方向通过白名单时输出 `'left'\|'right'`，否则 `null` |

### 4.4 方向白名单与 `invalidDirection`（D-3 闭环，唯一定义）

#### 4.4.1 白名单

#### 4.4.2 `invalidDirection` 的唯一定义（消除 v2 §4.2 / §4.4 的冲突表述）

**定义**：`invalidDirection` 是**「可显示状态的方向校验失败」标记**，**不是**「任意状态的非法载荷」标记。

```
displayableState = (state ∈ {resolved, remote}) ∨ (state === 'overridden' ∧ overrideSource === 'manual')

invalidDirection === true  ⇔  displayableState === true  ∧  白名单未产出合法方向
```

- **校验范围**：白名单对**所有 state** 都执行（用于决定 `direction` 是否可用）；
- **置位范围**：仅 `displayableState === true` 时置位；不可显示状态（`conflict` / `undetermined` / `unlinked` / `none` / `overridden(fire-avoidance)` / 未知来源）即便载荷非法也**保持 `false`**。

**为什么不是「任意状态」**（三条）：① 不可显示状态的 `direction` 从不被读取/输出，置位只产生无语义噪声；② 若一律置位，测试无法区分「脏载荷」与「正常降级」，断言退化为恒真；③ 与 `stale` 的分工会被打乱 —— `stale` 表达「有历史值但本轮无效」，`invalidDirection` 表达「本轮裁决载荷本身坏了」。

**行为矩阵（实现、测试、UI 三方共同基线）**

| state / 来源 | 方向合法 | `direction` | `showArrow` | `invalidDirection` | `stale`（有合法历史值时） |
|---|---|---|---|---|---|
| `resolved` | 是 | `left/right` | true | false | false |
| `resolved` | 否 / 缺失 | null | false | **true** | true |
| `remote` | 是 | `left/right` | true | false | false |
| `remote` | 否 / 缺失 | null | false | **true** | true |
| `overridden(manual)` | 是 | `left/right` | true | false | false |
| `overridden(manual)` | 否 / 缺失 | null | false | **true** | true |
| `overridden(fire-avoidance)` / 未知来源 | 任意 | null | false | **false** | true |
| `conflict` / `undetermined` / `unlinked` / `none` / 未知 state | 任意 | null | false | **false** | true |

**UI 使用边界**（不扩范围）：本批**不新增任何**基于 `invalidDirection` 的文案分支；界面表现即「无箭头 +（有历史值时）`stale` 提示」。该字段只用于测试断言与脏数据定位。
