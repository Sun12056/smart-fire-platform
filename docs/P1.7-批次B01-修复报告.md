## 一、状态链审计：第一步 processing 的权威来源

链路：`RESET → Backend(snapshot) → WS → demoStore → platformStore → DemoPanel`

| 环节 | 位置 | RESET 后的实际值 |
| --- | --- | --- |
| Backend | `DemoRoom` 广播 | `{"type":"demo.stage","stage":"IDLE","stageIndex":0,...}` |
| WS | 前端 `DemoSocket.onMessage → handleMessage → applySnapshot` | 收到，快照已应用 |
| demoStore | `stageIndex = snap.stageIndex ?? 0`（`demoStore.js:107`） | `IDLE` / `stageIndex = 0` |
| demoStore.flowSteps | `active: stageIndex === i+1`、`done: stageIndex > i+1 \|\| stage==='COMPLETED'`（`demoStore.js:57-65`） | **六步全部 pending（正确）** |
| platformStore.demoStepIndex | `platformStore.js:41-50` | **IDLE 时返回 `0`（缺陷点）** |
| DemoPanel.stepStatus | `DemoPanel.vue:163-168`：`idx === cur → 'processing'` | 第 0 步被渲染成 **processing** |

**结论**：权威投影（`demoStore.flowSteps`）本身完全正确，六步已算出全 pending。
缺陷在 `platformStore.demoStepIndex` —— 它把 `i <= 0`（IDLE，语义是「流程未启动」）
**折叠成了索引 0**（语义变成「停在第 1 步」），于是 `DemoPanel` 的 `idx === cur` 命中第 0 步，凭空造出一个 processing。

这是**状态投影错误**，不是组件没清空，也不是后端没复位。

## 三、最小修改

`src/stores/platformStore.js`，只改投影口径（+7/-1）：

```diff
  const demoStepIndex = computed(() => {
    if (dataSource.isDemo) {
      const i = demoStore.stageIndex
-     if (i <= 0) return 0
+     // P1.7 批次 B-01：IDLE 时 stageIndex=0 语义是「流程未启动」而非「停在第 1 步」，
+     // 返回 -1（无当前步）让六步全部 pending；判据仍取自后端 snapshot 派生的 demoStore.stageIndex，
+     // 不在组件里硬编码清空，RESET 后由 WS 快照驱动自动归零。
+     if (i <= 0) return -1
      return Math.min(i - 1, 5)
    }
    const s = fireStore.emergencyStage
    if (!s || s <= 0) return 0
    return Math.min(s - 1, 5)
  })

- const currentStep = computed(() => demoFlowSteps.value[demoStepIndex.value])
+ // demoStepIndex 可能为 -1（流程未启动），这里做安全取值
+ const currentStep = computed(() => demoFlowSteps.value[demoStepIndex.value] || null)
```

要点：

- **不新增状态机、不改后端契约**，只修正 demo 分支的状态投影。
- **由后端状态/WS snapshot 驱动归零**：判据是 `demoStore.stageIndex`（唯一来源是后端 snapshot `stageIndex`），
  RESET 快照回来后 `stageIndex=0 → -1`，六步自动全 pending；组件里没有任何硬编码清空。
- `currentStep` 加安全取值（`startDemoFlow` / `advanceDemoFlow` 在 demo 模式均提前 return，只有 mock 分支会用到它）。
- mock 分支（`fireStore.emergencyStage`）保持原样，未改动，避免影响 mock 模式既有行为。
