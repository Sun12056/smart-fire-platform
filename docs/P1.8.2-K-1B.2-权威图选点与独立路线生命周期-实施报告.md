## 二、每个修改文件的职责

### 2.1 `src/stores/fireStore.js`

1. **新增导入**：`NODE_TYPE`、`floorNum`（自 `routeGraph.js` 重导出）；`EXIT_NODE_IDS`（自 `floorTopology.js`）。

3. **独立数据源**：`manualExecutableRoutes`（手动可执行路线）、`manualRouteDrafts`（自由绘制草稿），二者生命周期分离。
4. **权威图选点状态与约束**：`authGraphPath` / `authGraphDraftId` / `authGraphError`；`authAdjacentNodeIds`、`isAuthStartNode`、`isAuthExitNode`、`canAuthStep`（含下降方向约束）、`pickAuthGraphStart`、`appendAuthGraphNode`、`undoAuthGraphStep`、`cancelAuthGraphSelection`、`resetAuthGraphSelection`、`loadAuthGraphRouteForEdit`、`saveAuthGraphRoute`。
5. **路线构建与生命周期**：`buildManualExecutableRoute`（校验 + 派生 `points`/`floorsPassed`）、`createManualExecutableRoute`（防重复 ID）、`replaceManualExecutableRoute`（按 ID 替换）、`deleteManualExecutableRoute`（按 ID 移除）、`sanitizeManualExecutableRoutes`（结构损坏 vs 拓扑失效分离）、`genManualRouteId`。
6. **自由绘制草稿化**：`saveManualRoute` 改写入 `manualRouteDrafts`（不再写入 `routePlans`）；新增 `deleteManualRouteDraft`。
7. **持久化接入**：`manualExecutableRoutes` 加入 `persistRefs`；恢复后执行结构清洗并记录 `manualRoutesRestoreReport`。

### 2.2 `src/views/RoutePlanView.vue`

## 三、独立路线数据结构与生命周期

### 3.1 手动可执行路线（`manualExecutableRoutes` 元素）

```js
{
  id: 'RP-MANUAL-<ts36>-<rand36>',   // 稳定且唯一
  type: 'manual-executable',
  buildingId: 'B003',
  startNode: '5F:A_CENTER',          // 权威图节点 id
  exitId: '1F:EXIT_W',               // 规范出口节点 id（= 终点节点）
  nodes: ['5F:A_CENTER', ..., '1F:EXIT_W'], // 权威图节点 id 序列
  points: [{ id, x, y, floorId }],   // 从权威图节点派生
  floorsPassed: ['5F','4F','3F','2F','1F'], // 从权威图节点派生
  createdAt: 1700000000000,
  updatedAt: 1700000000000,
}
```

**明确不含**：`validated`、`reachable`、`valid`、`status`、`recommended` 等可信运行时结论字段（测试已断言）。

### 3.2 生命周期

| 操作 | 函数 | 规则 |
| --- | --- | --- |
| 新建 | `createManualExecutableRoute` | 未提供 id 时生成唯一 `RP-MANUAL-…`；重复 id 返回 `DUPLICATE_ID` 拒绝 |
| 替换（编辑保存） | `replaceManualExecutableRoute` | 按 id 定位替换，保留原 `createdAt`，更新 `updatedAt`，不累积重复项 |
| 删除 | `deleteManualExecutableRoute` | 显式按 id 过滤移除，返回是否发生删除 |
| 草稿 | `saveManualRoute` / `deleteManualRouteDraft` | 写入 `manualRouteDrafts`（`RP-MANUAL-DRAFT-…`），与独立路线完全隔离 |

### 3.3 与既有数据结构隔离

`manualExecutableRoutes` **不并入** `routePlans`、`routeMatrix.perZone`、`activeBuildingPlan.routes`；不向自动路线推荐/备用/选中指针注入手动路线（专项测试第十二节断言三者 JSON 不变）。

## 四、权威图选点实现及边约束

- **图来源**：`authoritativeRouteGraph`（`buildBuildingGraph` + 真实现有 `getBuildingFloors`），UI 与校验共享同一份图；`RoutePlanView.vue` 不重复推导楼栋层数与建图。
- **起点**：仅 `type === ROOM || DOOR`（当前权威图实际只有 ROOM 类房间门口节点，谓词兼容 DOOR）。
- **后续节点**：只能从 `graph.adj[currentNodeId]` 真实邻接中选，杜绝坐标距离 / 最近吸附 / 自由绘制 / 名称推断。
- **跨楼层（下降边）**：`canAuthStep` 额外要求跨层必须满足 `floorNum(from) > floorNum(to)`，即**只允许下降、不允许上升**；楼梯停用（如 6F 的 STAIR_NW/S-A）导致下降边不存在，无法跨层。
- **终点**：仅 `EXIT_NODE_IDS`（`1F:EXIT_W` / `1F:EXIT_E`）可作为终点；`exitId` 强制等于终点节点 id，不通过「出口 A/B」文字或坐标推断。
- **编辑交互**：已选路径序列、继续选点、撤销上一步、取消编辑、重新选点、更换终点、载入既有路线进入替换模式。

## 五、持久化与旧快照兼容

- `manualExecutableRoutes` 加入 `persistRefs`（草稿 `manualRouteDrafts` 不持久化）。
- 旧快照缺少 `manualExecutableRoutes` 字段时：`restorePersistSnapshot` 跳过该 key，恢复后清洗逻辑将 ref 置为空集合（默认值），不抛错。
- 恢复时结构清洗 `sanitizeManualExecutableRoutes`：
  - **结构损坏**（非对象 / id 缺失 / `nodes` 非字符串数组 / `exitId` 非字符串）→ 剔除并写入 `manualRoutesRestoreReport`（可诊断）。
  - **结构完整但拓扑可能失效** → 保留（作为不可执行历史/待编辑路线），不因校验失败静默删除；后续 K-1B.3/K-1B.4 决定展示与重验证。
- 仅持久化原始路线数据（节点 id、坐标、楼层），不含临时图/邻接缓存/校验结论/出口状态；序列化对象为纯 JSON（构造时均为 id/坐标标量，无循环引用、无响应式代理）。
