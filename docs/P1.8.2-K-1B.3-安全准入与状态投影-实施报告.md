## 三、数据契约

### 3.1 拓扑有效性判定
- `validateManualRouteNodes(nodes, graph)`：纯函数，对任意图校验结构 / 起点类型 / 节点存在 / 逐段真实邻接+下降 / 终点为规范出口。不依赖当前 UI 选点状态。
- `graphForBuilding(buildingId)`：按**指定楼栋**建图（`buildBuildingGraph(getBuildingFloors(buildingId))`），楼栋缺失/不存在/层数非法/建图失败返回明确原因。
- `validateManualRouteTopology(route)`：用 `route.buildingId`（所属楼栋，非当前 UI 楼栋）取图校验，并核对 `exitId === 末节点`，输出三态 `VALID / INVALID / BUILDING_UNAVAILABLE` + `reason`。

### 3.2 出口运行时可用性独立表达
- `manualRouteExitVerdict(route)`：基于 `exitRawStates` / `exitReportedUsableNodeIds`（真实上报可用集）：
  - `exitRawStates === null`（从未收到上报）→ `UNKNOWN`（无法得出可用性结论）。
  - 否则 `exitReportedUsableNodeIds.includes(exitId)` → `AVAILABLE` / `UNAVAILABLE`。
- 与拓扑结论完全独立，二者不合并为单一布尔。

### 3.3 执行状态 / 设备下发不属于拓扑准入
- 投影只含 `topologyStatus` / `topologyReason` / `exitStatus` / `exitReason` 四个字段，不定义 `execution` / `dispatch`；「拓扑有效」不表达「可安全执行」。

### 3.4 旧快照兼容
- 投影是 computed 只读派生，不回写路线对象、不持久化、不新增持久化字段；旧快照仍由 `sanitizeManualExecutableRoutes` 恢复，无需迁移。

### 3.5 保留拓扑失效路线及诊断
- 投影只报告不删除；诊断信息位于 `topologyReason` / `exitReason`，路线原始数据保留。

## 四、准入规则（`validateManualRouteTopology`）

| 检查 | 失败原因 |
| --- | --- |
| 路线为对象 | `INVALID_ROUTE_OBJECT` |
| 所属楼栋存在且可建图 | `BUILDING_MISSING` / `BUILDING_NOT_FOUND` / `BUILDING_FLOORS_INVALID` / `BUILDING_GRAPH_FAILED` → `BUILDING_UNAVAILABLE` |
| 节点序列结构 + 长度 ≥ 2 | `PATH_TOO_SHORT` |
| 起点类型 ROOM/DOOR | `INVALID_START_TYPE` |
| 所有节点存在于所属楼栋图 | `UNKNOWN_NODE` |
| 逐段真实邻接 + 下降方向 | `NOT_ADJACENT` |
| 终点为规范出口 | `INVALID_EXIT` |
| `exitId` 与末节点一致 | `EXIT_ID_MISMATCH` |

## 五、状态投影（`manualRouteStatusView`）

computed 派生，为每条手动路线返回：
```js
{ id, topologyStatus, topologyReason, exitStatus, exitReason }
```
- `topologyStatus ∈ { VALID, INVALID, BUILDING_UNAVAILABLE }`
- `exitStatus ∈ { AVAILABLE, UNAVAILABLE, UNKNOWN }`
- 不回写 `manualExecutableRoutes`、不写 `validated` / `reachable` / `status`，不持久化。
