## ② 每个守卫点说明

统一形式：`if demo mode → 早退（不写任何业务状态）；mock / api → 保留原逻辑`。

### B1-01 阶段写入

| 函数 | demo 返回 | 封锁的写入 | mock/api |
|---|---|---|---|
| `detectFireScenario` | `false` | `fireEvent`、`emergencyStage=1`、局部设备 `warning` | 原逻辑 |
| `startDemoFlow` | `false` | 本地发现火灾全流程 | 原逻辑 |
| `advanceDemoStage` | `false` | 按 `emergencyStage` 自行迁移阶段 | 原逻辑 |
| `generateEvacuationOptions` | `[]` | `emergencyStage=3`、本地方案生成 | 原逻辑 |
| `syncStageAfterExternalFire` | `false` | 外部页面本地触发火灾后的阶段同步 | 原逻辑 |
| `finishEvacuation` | `undefined` | `emergencyStage=5` 本地结算 | 原逻辑 |
| `resetEmergencyFlow` | `false` | `emergencyStage=0`、人员坐标整体复位 | 原逻辑 |

说明：`activateEmergencyResponse` / `confirmEvacuationPlan` / `confirmStrandedLocation` / `dispatchRescueTeam` / `startEvacuationRun` 沿用 P1.7.2 已有的 `dispatchDemoCommand` 短路，**未改动**。
demo 模式下 `emergencyStage` 现在只由 `applyDemoSnapshot:362` 从后端 stage 单向派生。

1. `worker/e2e-phase2-consistency.cjs` 楼栋隔离：B1 之前 demo 会为 B001/B002/B004 本地生成方案；B1 之后范围 authority only → 断言改为「方案属于当前楼栋 **或 该楼栋确无方案（null）**」，真正禁止的仍是「渲染别栋方案」。
